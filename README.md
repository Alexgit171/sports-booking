## Назначение

Сервис помогает пользователю выбрать спортивную площадку, проверить свободное время и оформить бронирование. Владельцу площадки он позволит управлять расписанием и заявками.

## Целевая аудитория

Любители спорта, тренеры, организаторы любительских команд и администраторы спортивных объектов.

## Предметная область

Почасовая аренда спортивных площадок. У площадки есть расписание и стоимость часа. Пользователь выбирает временной интервал, а сервис проверяет его доступность и рассчитывает стоимость. Бронирования одной площадки не должны пересекаться по времени.

## Основные сущности

- **Пользователь:** человек, который оформляет бронирование; в ПР1 представлен именем.
- **Площадка:** спортивный объект с названием и ценой аренды; в ПР1 одна демонстрационная площадка.
- **Время:** дата и интервал аренды; в ПР1 дата фиксирована, часы задаются целыми числами.
- **Бронирование:** связь пользователя, площадки и времени с итоговой стоимостью; в ПР1 выводится текстовое подтверждение.

## Основные функции

На ПР1 реализованы три функции предметной области:

1. `is_slot_available(start_hour, duration)` проверяет часы работы и пересечение с занятым интервалом.
2. `calculate_price(duration, hourly_rate)` рассчитывает стоимость аренды.
3. `create_booking(user_name, start_hour, duration)` проверяет имя и доступность, затем формирует подтверждение либо причину отказа.

`main()` организует ввод и вывод в консоли. Перед преобразованием введённых значений в числа проверяется их формат. Использованы `str`, `int`, `float`, `bool`, арифметика, сравнения, преобразование типов, ветвления, функции и импорт `date` из `datetime`.

## Правила демонстрации

- Площадка: «СпортПарк», мини-футбол.
- Дата: **01.10.2026**, фиксированная учебная дата.
- Часы работы: **08:00–22:00**.
- Уже занято: **18:00–20:00**.
- Цена: **1 500 рублей за час**, учебное значение.
- Начало и длительность вводятся целыми часами; длительность положительна.
- Интервалы считаются полуоткрытыми: окончание ровно в 18:00 и начало ровно в 20:00 допустимы.
- Один запуск обрабатывает одну заявку. Подтверждение демонстрационное: данные не сохраняются, новое бронирование не изменяет расписание последующих запусков.

## Запуск

В установленном Python 3:

```bash
python main.py
```

Пример ввода: имя `Александр`, начало `16`, длительность `2`. Результат: бронирование с 16:00 до 18:00, стоимость 3000.00 руб.

Пример отказа: начало `17`, длительность `2` пересекается с интервалом 18:00–20:00.

Виртуальное окружение, Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m unittest -v
```

Linux/macOS:

```bash
python3 -m venv .venv
.venv/bin/python main.py
.venv/bin/python -m unittest -v
```

Внешние библиотеки для программы и приложенных тестов не требуются. Активация окружения необязательна, если интерпретатор вызывается по полному относительному пути.

## Проверка и отладка

`test_main.py` содержит проверки границ времени, пересечений, стоимости, пустого имени и ввода в консоль. Это вспомогательная проверка на стандартном `unittest`, не функциональность приложения. Классы и коллекции в проверках не относятся к реализации ПР1 в `main.py`.

В `evidence/` сохранены результаты запуска, тестов и сеанса `pdb`. Настройка запуска VS Code находится в `.vscode/launch.json`. Подробная инструкция отладки и намеренной ошибки приведена в `../START_HERE.md` из архива.

## План развития

- **ПР2:** коллекции, циклы, функции обработки заявок, модули, файлы, исключения и типизация; несколько площадок и сохранение бронирований.
- **ПР3:** классы пользователя, площадки, временного интервала и бронирования.
- **ПР5–ПР6:** Django-проект, адреса страниц, представления и HTML-шаблоны каталога и расписания.
- **ПР7–ПР9:** база данных, модели Django ORM, связи сущностей и административный интерфейс.
- **ПР10–ПР11:** формы бронирования, регистрация, вход и права пользователей; создание, просмотр, изменение и отмена собственных заявок.
- **ПР13–ПР15:** автоматизированные тесты и проверка конфликтующих бронирований.
- **Дальнейшие этапы:** REST API, контейнеризация в Docker и настройка CI/CD.
